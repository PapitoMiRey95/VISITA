## Root cause
The backend container/process is healthy and bound on :8001; the frontend worker is up. The failure is in the **Cloudflare-worker → Kubernetes-backend proxy hop**, which is returning 502/503 so `/api` requests never reach the pod. The full path worked for ~16h after promote (external /api served 200 until ~17:43) and then the edge→backend connectivity dropped — the backend did not crash (localhost readiness still green, 0 restarts).

**This is an infrastructure/platform issue (edge↔backend routing), NOT a code regression in `network.py` and NOT a missing/empty secret or config.** A code regression would have failed at health_check/promote and would show a crashed/restarting pod — neither is present.

## Suggested fixes
1. **Platform (Emergent infra):** Investigate the Cloudflare worker → k8s backend Service routing for this deployment on `deployment-cluster-03` / namespace `customers-app` (workload `r-1aa5999d-8142-4948-a976-f5867f61b9fa`). The backend Service/tunnel/ingress is returning 502/503 while pod endpoints are Ready — likely a stale/dropped tunnel registration or Service-endpoint binding that broke ~17:43 UTC. This is the primary fix.
2. **User (workaround, optional):** A fresh redeploy recreates the pods and re-registers the backend with the edge, which typically clears a stale tunnel/endpoint and restores `/api`. This is a mitigation, not the root fix.

## Explicitly ruled out
- `network.py` regression / startup crash (app running, imports clean, no traceback).
- Missing/empty secret (all present on active run).
- Mongo connectivity (DB routes served 200).
- OOM / tier limit (no OOMKilled, 0 restarts).
- Custom domain / DNS / SSL (domains verified, SSL active; also fails on default emergent.host).
- App maintenance-mode / readiness gate (those return JSON; this is a Cloudflare edge error page).
