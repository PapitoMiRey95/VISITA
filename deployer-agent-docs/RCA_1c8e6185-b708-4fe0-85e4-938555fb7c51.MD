## Why the redeploys failed (context)
`server.py:9753` startup → `audit_view.ensure_indexes` → `db.audit_logs.create_index(...)` runs **synchronously inside the FastAPI lifespan** and is **fatal** on error. On the failing runs it raised `pymongo.errors.NetworkTimeout` (read op timed out, socketTimeoutMS 60000) → `Application startup failed. Exiting` → nginx shut down → `/health` 503 → rollout timed out. The last run even logged the bootstrap as a non-fatal WARNING in places yet still timed out the rollout, so behavior is inconsistent.

## Suggested fixes
- **Code (E1):** make `ensure_indexes` non-fatal and non-blocking at startup — wrap in try/except so a timeout logs a warning instead of killing the lifespan, and/or move index creation to a background task after the app reports ready. Indexes on a 1135-doc collection should not gate liveness.
- **User / third-party (Atlas):** the repeated `NetworkTimeout` to `customer-apps-shard-00-02.zbnnya.mongodb.net:27017` points at transient cluster/network slowness during the deploy window — verify Atlas cluster health and, if desired, pre-create the 5 missing indexes directly in Atlas so startup finds them already present.
